# Место — инфраструктура проекта

Этот репозиторий содержит Docker-конфигурации, общий Nginx, маршрутизацию событий Kafka, шаблон окружения и команды запуска проекта. На компьютере его нужно клонировать в папку **ONMI_infra**, рядом с папками `services` и `java_services`.

**Установка на чистом компьютере:** [пошаговая инструкция](docs/LOCAL_SETUP.md). Она включает все девять репозиториев, структуру папок, подготовку `.env`, генерацию JWT-ключей, запуск, миграции, проверку и остановку без удаления базы.

После подготовки окружения выполняйте команды из `ONMI_infra`:

```bash
make registration-check
make registration-up
make registration-ps
```

| Адрес | Назначение |
| --- | --- |
| http://localhost:8080 | Сайт |
| http://localhost:8080/cabinet | Личный кабинет после входа |
| http://localhost:8025 | Тестовые письма Mailpit |

`registration-up` и его синоним `web-up` запускают весь локальный стек, включая catalog-service, устанавливают PHP-зависимости, применяют миграции пяти сервисов и перезагружают общий Nginx. Несмотря на название команды, это основной локальный режим проекта.
Повторный запуск использует уже собранные образы; после изменения Dockerfile или Java-кода выполните `make registration-rebuild` для принудительной пересборки и полного запуска.

```bash
make registration-logs
make registration-logs SERVICE=catalog-service
make registration-cache
make registration-down
```

Остановка сохраняет том PostgreSQL. Не используйте команды удаления томов для обычного перезапуска. Не запускайте параллельно прежний стек `make up`/`make bootstrap`: он использует те же имена контейнеров, но другие настройки хранения и не включает Mailpit. Обычный `docker compose up` также не заменяет локальный запуск: Makefile собирает конфигурацию из файлов `compose/`.

Сертификаты Минцифры разрешены **только внутри Docker-образа catalog-service**, для запросов GigaChatClient. Установка в macOS/ОС хоста, Keychain или глобальные хранилища доверия запрещена. Образ каталога отделён от общего PHP-образа.

Реальные `.env`, API-ключи, приватные JWT-ключи, данные базы и зависимости `vendor` не передаются через Git. После изменения документации и конфигурации сохраните и отправьте изменения этого репозитория; исходный код каждого сервиса сохраняется в его собственном репозитории.
